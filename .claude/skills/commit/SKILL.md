# commit

변경사항을 분석해 논리적 단위로 나누고, 컨벤션에 맞는 한국어 커밋 메시지로 커밋한다.

## 절차

1. **변경사항 분석**
   - `git status --short`, `git diff`, `git diff --staged`로 변경 내용을 확인한다.
   - untracked 파일은 내용을 직접 확인한다. `.env` 등 비밀 값이 포함된 파일은 커밋 대상에서 제외하고 사용자에게 알린다.

2. **논리적 단위로 분류**
   - 목적이 같은 변경끼리 묶는다 (기능 추가, 버그 수정, 리팩터링, 설정/문서 등).
   - 서로 다른 목적의 변경은 별도 커밋으로 나눈다.

3. **한국어 커밋 메시지 작성**
   - 형식: `type: 요약`
   - type: `feat`(기능 추가), `fix`(버그 수정), `refactor`(동작 변경 없는 구조 개선), `chore`(설정/빌드/잡무)
   - 요약은 한국어로 간결하게 쓰고, 필요하면 본문에 이유를 덧붙인다.

4. **사용자 승인 후 커밋**
   - 분류 결과와 커밋 메시지를 먼저 보여주고 **승인을 받은 뒤에만** 커밋한다.
   - 승인 전에는 `git add`, `git commit`을 실행하지 않는다.
   - 커밋 후 `git status`와 `git log --oneline`으로 결과를 확인해 보고한다.

## 주의

- 파일은 이름으로 지정해 스테이징한다. 무분별한 `git add -A`를 피한다.
- 훅 실패 시 `--no-verify`로 우회하지 말고 원인을 해결한다.
- 기존 커밋을 `--amend`하거나 `push`하는 것은 사용자가 요청한 경우에만 한다.
